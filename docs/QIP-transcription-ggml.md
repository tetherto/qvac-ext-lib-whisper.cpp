## Summary

Replace `@qvac/transcription-whispercpp` (0.12.1) and `@qvac/transcription-parakeet` (0.10.1) with one multi-engine `@qvac/transcription-ggml` package, following the proven `@qvac/tts-ggml` shape: one public class with static engine constants, one Bare addon dispatching on `engineType`, one CI/benchmark family instead of two. Migration preserves git history (`git mv`), keeps the SDK green throughout (addon-only merge — the SDK's two plugins and two `modelType`s survive unchanged until the separate repoint ticket), and **does not block on the umbrella vcpkg port**: the addon consumes today's `whisper-cpp` + `parakeet-cpp` ports side-by-side (they already share one `ggml-speech`), and swaps to `speech-cpp[whisper,parakeet]` later as an invisible dependency change.

Material amendments to the original plan, from auditing the packages as they exist today (2026-07-23, `qvac@6ae29cb7`) and from an adversarial review pass over the first draft:

1. **`tts-ggml` is not the driver-table design the plan implies** — it is one monolithic orchestrator class (~950 lines) with inline `engine ===` branches and a *flat, non-discriminated* options object. We adopt its **native** pattern verbatim (`createInstance` dispatch + `dynamic_cast` in `runJob`) but deliberately improve on its **JS** pattern with small internal per-engine drivers, because the two ASR surfaces diverge far more than chatterbox/supertonic do — and the drivers must own the *streaming pump and session lifecycle*, not just payload mapping (see Decision).
2. **Do not invent a third config vocabulary.** The public config is discriminated by `engine`, but each branch keeps its engine's existing, allow-listed field set (`whisperConfig` snake_case incl. `configChecker` rules; `parakeetConfig` camelCase incl. the `streaming*`/`spkCache*` surface) verbatim. Normalization applies to the *method surface, streaming events, and audio input boundary* — not to per-engine tuning knobs. The same rule extends to `runStreaming` per-call options, which are also engine-scoped (whisper's `{emitVadEvents, endOfTurnSilenceMs, …}` vs parakeet's `{chunkMs, historyMs, spkCache*, …}` share no fields).
3. **CI-first sequencing, and an explicit npm-release step.** The migration below starts with a PR 0 that lands the new CI family before anything moves (the repo-reorg's own precedent: CI PR #93 before move PR #95) — a rename-first PR cannot pass the base-branch `pr-gate-merge`/`on-pr-*` gates, which run against the old paths. And the SDK repoint hard-depends on `@qvac/transcription-ggml` existing on **npmjs**, which only a `release-*` merge produces — that release is a scheduled step, not an afterthought.
4. **The CI/benchmark port is the largest single work item** — 19 workflow files retired, ~10 created, 8+ central registries edited, two Python WER/CER harnesses and two RTF aggregators merged, plus Device Farm secrets provisioning. Planned explicitly below, including the ordering constraints on registries that reference *published* packages.

## Problem

Two ASR packages duplicate the same stack — Bare addon on `qvac-lib-inference-addon-cpp` (vcpkg) ≥1.2.4, `cmake-bare`/`cmake-vcpkg`, TypeScript two-layer JS (orchestrator + native interface), brittle tests, Python WER/CER benchmark harness, and a per-package CI family of 9–10 workflows each — while diverging in API shape:

- Constructor: `new TranscriptionParakeet({ files, config, logger, exclusiveRun })` vs whisper's two-positional-arg `new TranscriptionWhispercpp({ files, logger, exclusiveRun, opts }, config)`.
- Config: `config.parakeetConfig` camelCase vs `config.whisperConfig` snake_case, with a fragile JS↔native key-translation layer (`NON_ADDON_WHISPER_KEYS`, `max_seconds`→`duration_ms`) on the whisper side.
- Streaming: whisper emits typed `{type:'vad'}` / `{type:'endOfTurn'}` events (Silero VAD, `files.vadModel`); parakeet has no typed events — EOU is a boolean `isEndOfTurn` on segments, VAD an `emitEnergyVad` flag.
- Semantics that diverge *silently*: `exclusiveRun` holds the queue slot until job completion on whisper but only until submission on parakeet; whisper's constructor throws on a missing model file, parakeet's warns; whisper's `pause()` throws "not supported", parakeet's "succeeds" as a JS-only state flip; parakeet's documented `enableStats` is dead code (stats always attach) while whisper gates on `opts.stats`.
- Duplicated-and-skewing: the `BackendId` enum, the `s16le`→f32 audio conversion, mock-binding test scaffolding, benchmark servers/clients, and the entire workflow family.

The SDK dispatches by `modelType` through a plugin registry; the packages are *imported* only in two plugin files at load time. `@qvac/tts-ggml` already proves the one-package/multi-engine model (and the SDK already absorbed one package consolidation, `onnx-tts` → `tts-ggml`, via alias mapping in `engine-addon-map.ts`).

## Audit findings

Facts verified against `tetherto/qvac@6ae29cb7` that correct the original draft (design-review findings are folded into Decision/Migration where they bite):

1. **Versions and language moved on**: whispercpp is 0.12.1, parakeet 0.10.1, tts-ggml 0.5.1. All three are **TypeScript** (`src/*.ts` → committed generated JS + `.d.ts`, enforced by `check:generated`) — whispercpp via [qvac#3336](https://github.com/tetherto/qvac/pull/3336), parakeet #3315, tts-ggml #3340. The merged package is TS from day one.
2. **`tts-ggml`'s real anatomy**: a ~950-line `TTSGgml` class, flat `TTSGgmlOptions` (both engines' fields co-mingled), engine auto-detect from *structurally distinct file keys* (no file I/O), dispatch via `_buildChatterboxParams`/`_buildSupertonicParams` ternaries. Native side: `JSAdapter::readEngineType()` → `make_unique<{Chatterbox,Supertonic}Model>` in `createInstance`; `dynamic_cast` in `runJob`/`reload`; both models implement `IModel`/`IModelCancel`/`IModelAsyncLoad`. Its exports map is **not** a single `"."` — it carries utility subpaths (`./text-chunker`, `./addonLogging`). The rule worth copying is *no per-engine subpaths*, not *no subpaths*.
3. **The C++ layers are near-twins, but "near" hides real merge work**: same framework interfaces, same core binding verbs, same worker-thread StreamingProcessor design with a global session map keyed by `AddonJs*`, same dynamic ggml-backend staging (`libqvac-speech-ggml-*.so` → `prebuilds/<subdir>`, `BACKENDS_SUBDIR`). Deltas that are *work, not renaming*: (a) the **log hooks clobber each other** — whisper installs `whisper_log_set` per-instance (which re-applies to ggml), parakeet installs a raw once-per-process `ggml_log_set` trampoline with line buffering; in one process the last-installed forwarder wins and the other engine's logs reroute — the merged addon needs one unified process-wide forwarder; (b) teardown differs — whisper registers an `atexit` that destroys its session map, parakeet doesn't and its teardown joins a worker thread (never exercised during static destruction); one session registry needs a deliberate teardown story; (c) binding signatures disagree (`appendStreamingAudio` void vs `Promise<boolean>` back-pressure; `endStreaming` void vs teardown-object) — the union surface is signature reconciliation, not renaming; (d) parakeet exports `getBackendInfo` (sync post-load query), whisper has no such verb — its backend data arrives only in `RuntimeStats` at `JobEnded`; a unified `getBackendInfo()` requires a **new whisper native verb** (small, and it must coordinate with in-flight [#3314](https://github.com/tetherto/qvac/pull/3314), which touches exactly this surface); (e) whisper has a native `reload` (context rebuilt only when context-affecting params change), parakeet reloads by destroy+recreate in JS — the `supportsReload` driver hook is grounded.
4. **The JS layers are where the divergence lives** — including lifecycle semantics (exclusiveRun, pause, validation strictness, stats gating; see Problem) that any unification must *decide*, not paper over. This is why the unified orchestrator needs per-engine drivers rather than tts-ggml's inline branches.
5. **SDK reality check**: dispatch is by `modelType` (registry `Map`), and only `packages/sdk/server/bare/plugins/{whispercpp,parakeet}-transcription/plugin.ts` *import* the packages. But the SDK's zod discrimination for transcription is keyed by **`modelType`** (two separate schema branches), *not* by an `engine` field — the engine-keyed union is the TTS pattern. Beyond imports, the old package **names** live in more places than the first draft listed: `sdk/contract/model-type-maps.json`, the generated `sdk-python` `model_type_maps.py`, `ai-sdk-provider/models/update-models/schemas.ts`, SDK naming tests — and, operationally live, `registry-server/data/models.prod.json`, where whisper model entries carry `"engine": "@qvac/transcription-whispercpp"`. The plugins also import *types* (`WhisperConfig` etc.), so the repoint is imports + types + constants, not imports alone. The whisper plugin already special-cases `endOfTurn.source === 'parakeet'` — a `source` field on end-of-turn events is precedented.
6. **Ticket 4 has not started**: the registry has no umbrella `speech-cpp` port — only `whisper-cpp` (1.9.1#4), `parakeet-cpp` (date-pinned), `tts-cpp`, `ggml-speech`. Both ASR ports declare `ggml-speech version>= 2026-07-15`, and the repo-reorg umbrella build has already validated whisper+parakeet linking one ggml. Two caveats for Phase A, neither blocking: parakeet-cpp enables ggml-speech default features, so whisper-cpp's `default-features: false` discipline is nullified in the merged install graph (no trimmed-ggml lanes until Phase B); and the two ports pin different snapshots of the same source repo until the umbrella port unifies the pin.
7. **Beyond the SDK, two more consumers/reference points**: `@qvac/tts-ggml` devDepends on `@qvac/transcription-whispercpp` (its WER/CER quality benchmark runs Whisper over synthesized audio, QVAC-22636), and `on-pr-bare-sdk-e2e.yml` npm-installs the whisper package. Both need repointing after the first npm release.
8. **Naming hazard that the new name fixes**: `bci-whispercpp` is a *separate, surviving* package whose workflow files match the `*whispercpp*.yml` path globs used by the whisper family today — every `*whispercpp*` match must be checked against it before deletion. `transcription-ggml` has no substring collision with anything.
9. **In-flight PRs against the old packages** ([#3314](https://github.com/tetherto/qvac/pull/3314) Core ML backend reporting, [#3228](https://github.com/tetherto/qvac/pull/3228) RNN-T support, [#3126](https://github.com/tetherto/qvac/pull/3126)/[#3130](https://github.com/tetherto/qvac/pull/3130) lint chores). "Rebase onto new paths" understates the cost where the reshape *splits* files (rename detection can't follow `index.ts` → orchestrator + driver): **#3228 should land before PR 2 or be explicitly re-ported**; #3314 additionally overlaps the `getBackendInfo` unification (finding 3d) and should be sequenced with PR 1.
10. **Cleanup to take with the move, not replicate**: whisper's `addon/CMakeLists.txt` is dead (references nonexistent sources; sole consumer of the unused `mel_filters.bin`), its `package.json` exports a `./transcription-addon` path whose directory doesn't exist, and its `run()` path silently corrupts `Float32Array` input today (falls through to a byte-truncating iterator branch). None of these survive the merge.

## Decision

Create `@qvac/transcription-ggml` in `tetherto/qvac/packages/`, mirroring `tts-ggml` where it is strong (native dispatch, one addon, one CI family, exports discipline) and deliberately improving where ASR needs more (internal JS drivers owning the streaming lifecycle, engine-discriminated config, normalized streaming events).

### Public API

```ts
class TranscriptionGgml {
  static readonly ENGINE_WHISPER = 'whisper'
  static readonly ENGINE_PARAKEET = 'parakeet'
  // future: ENGINE_QWEN_ASR = 'qwen-asr'

  constructor(options: {
    files: { model: string, vadModel?: string /* whisper streaming */ }
    config?: { engine: 'whisper', /* whisperConfig vocabulary, verbatim */ }
           |  { engine: 'parakeet', /* parakeetConfig vocabulary, verbatim */ }
    engine?: string        // convenience alias when config is omitted; config.engine wins
    enableStats?: boolean  // method-surface knob (see below), default true
    logger?: LoggerInterface
    exclusiveRun?: boolean // default true; unified semantics defined below
  })

  load(); unload(); destroy(); reload(newConfig?); cancel()
  getState(); status(); getEngineType(); getBackendInfo()
  pause(); unpause()      // structured NOT_SUPPORTED error until an engine truly supports them (see semantics notes)
  run(audio): Promise<QvacResponse<TranscriptionSegment[]>>
  runStreaming(audio, opts?): Promise<QvacResponse<StreamEvent>>   // opts engine-scoped, driver-validated
}
```

- **The discriminant lives inside `config`** (`config.engine`), so the union actually typechecks — TypeScript cannot narrow a config union from a *sibling* property. Top-level `engine` is a convenience alias for the config-less case. When neither is given, auto-detection is **best-effort convenience, not the contract**: today a magic-byte sniff discriminates reliably (whisper models are legacy GGML `.bin`, parakeet are GGUF — parakeet then self-detects CTC/TDT/EOU/Sortformer from metadata), but this stops working when a second GGUF engine (qwen-asr) arrives, at which point missing-`engine` + GGUF without recognizable metadata becomes an error. Docs and the SDK plugins always pass `engine` explicitly.
- **Exports**: `"."` + utility subpaths only (`./addonLogging`, `./binding.js`, `./package`) — the SDK imports `/addonLogging` today. The per-engine subpaths (`./parakeet`, `./transcription-addon`) are dropped.
- **Config**: each engine branch carries its existing allow-listed fields unchanged (whisper's `configChecker` moves into the whisper driver's `validateConfig`). No third vocabulary, no silent key remapping beyond what each package already does internally. `enableStats` and `exclusiveRun` are *method-surface* knobs (they govern the wrapper, not the engine) and are the only sanctioned top-level additions; note parakeet's current `enableStats` is dead code and whisper's lives in `opts.stats` — this is a unification of intent, defaulting to today's SDK-observed behavior.
- **Unified semantics (explicit decisions, not averages of today):** `exclusiveRun` serializes `run()` to *completion* (whisper's semantics; parakeet today releases at submission). `runStreaming` acquires the slot for session *setup* only, and concurrent `run()` against an open streaming session is rejected with a structured error — holding the queue for a minutes-long duplex mic session (whisper's current behavior) would wedge mixed workloads. Constructor-time model validation throws on a missing file for both engines (tightens parakeet's warn-and-continue). `pause()/unpause()` return structured NOT_SUPPORTED for both (whisper throws today; parakeet's "success" is a JS-only state flip that touches nothing native — preserving that would be preserving a bug). Whisper's public `stop()` (which already just throws) is retired, documented in the changelog.
- **Audio**: the boundary rule is *typed-array class discrimination* — `Float32Array` → f32, `Uint8Array`/`Int16Array` → s16le, chunk arrays and (async) iterables of either, 16 kHz mono. This is parakeet's rule promoted to the package boundary; **it is new code for the whisper driver**, whose current path corrupts `Float32Array` (finding 10) — the merge fixes that footgun rather than inheriting it. Whisper's `audio_format: 'decoded'` stays available inside its config branch.
- **Streaming events** — normalized union with a `source` field, scoped honestly: `segment` (common core `{text, start, end, id}` + engine extras like `startsWord`); `vad` `{speaking, score, source: 'silero'|'energy'}` — **whisper-only at launch**: the parakeet addon never wires the engine's `StreamEvent` API to JS today, so parakeet VAD events require new native plumbing (Phase 2, additive), and the field is `score`, not `probability`, because parakeet's engine documents it as provenance-specific (RMS-derived for energy VAD); `endOfTurn` `{silenceDurationMs?, source: 'vad-silence'|'model-eou'}` — whisper passes its typed event through; the parakeet driver synthesizes it from `isEndOfTurn` segments *in addition to* emitting the segment (double-signal, matching how the SDK consumes it today). One `BackendId` enum; `RuntimeStats` becomes a common core (`backendId`, `backendDevice`, timing totals) plus engine-specific extras — the two current shapes share almost no timing fields, so SDK code typed against either needs the type rename pass in PR 3.

### Internal structure

- **JS drivers** (internal, not exported): `src/engines/{whisper,parakeet}/` implementing `{ buildNativeConfig, validateConfig, normalizeAudio, buildStreamingOpts, mapSegment, mapStreamEvent, supportsReload }` **plus a driver-owned streaming strategy** (`createStreamingSession(audio, opts)` owning precondition checks, the pump loop, back-pressure, and teardown). The pump cannot live in the orchestrator: parakeet awaits per-chunk back-pressure (`appendStreamingAudio → Promise<boolean>`) and synthesizes `JobEnded` from a teardown object, whisper pumps synchronously, requires `vadModel` before touching native, and finalizes via a separate `finishStreaming` on response settlement — an orchestrator-owned loop would need exactly the `if engine ===` branches the driver table exists to eliminate. This is a stated departure from tts-ggml's monolith, justified by findings 3–4.
- **Native addon** — the tts-ggml pattern: one `BARE_MODULE`, `JSAdapter::readEngineType()` → `make_unique<{Whisper,Parakeet}Model>` in `createInstance`; `dynamic_cast` dispatch in `runJob`/`reload`. The models' *inference* code slots in as-is, but the merge owns four pieces of real native work (finding 3): one process-wide ggml/whisper log forwarder, one session registry with a defined teardown order (atexit story), reconciled streaming verb signatures, and a new whisper `getBackendInfo` verb. `BACKENDS_SUBDIR` must be defined on **every** target that compiles backend-path code (a latent bug of this kind exists in tts-ggml's CMake), and no direct ggml-cpu symbol calls (GGML_BACKEND_DL, the June Android regression).

### Dependency strategy (de-serializing Ticket 4)

- **Phase A (this QIP)**: `vcpkg.json` depends on **both** `whisper-cpp` and `parakeet-cpp` with today's per-platform backend features. Both resolve one `ggml-speech` (≥2026-07-15); coexistence on one ggml is proven by the repo-reorg umbrella build. Accepted Phase A costs (finding 6): ggml-speech default features are effectively always-on (parakeet-cpp's manifest wins), and the two ports pin different upstream snapshots. Risk to verify in PR 1/2 CI: duplicate-symbol or CMake-config clashes when both ports link into one Bare module (none expected — distinct libs, shared ggml).
- **Phase B (when Ticket 4 lands)**: swap to `speech-cpp[whisper,parakeet]` + platform backend features in one dependency-only PR — one source pin, restored feature discipline, invisible to consumers.

## Migration plan

All PRs in `tetherto/qvac`. **CI first, then moves** (the repo-reorg precedent: CI PR #93 before move PR #95) — a rename-first PR cannot pass the gates, because `pr-gate-merge.yml` and the `on-pr-*` families are `pull_request_target` and run the **base-branch** workflow versions: the old paths-filters match the deletions (dorny/paths-filter matches deletes), sending `prebuilds-caller` to build a directory that no longer exists at the PR head, while the new family — not yet on `main` — cannot run at all.

**PR 0 — CI scaffold.** Add the `transcription-ggml` workflow family (see porting table) and register it where registration is inert until the package exists: `pr-gate-merge.yml` paths-filter entry, `prebuilds-caller.yml` job, and the hardcoded workflow-name list in `.github/scripts/test/ci-trust-policy.test.mjs` (security-baseline reads every `on-pr-*` file by name — an unlisted family silently escapes the trust-policy checks; a deleted-but-listed one fails ENOENT). **Do not touch** `addons.js`, `gate-selftest.yml`, or coload-smoke yet — those reference *published npm packages* and must keep the old entries until the first `@qvac/transcription-ggml` npm release (coload-smoke installs from npm by design).
**PR 1 — whisper becomes the unified package (history-preserving).** `git mv packages/transcription-whispercpp packages/transcription-ggml` as a pure-rename commit, then reshape commits in the same PR: package rename, orchestrator + `src/engines/whisper/` driver, the semantics decisions above (exclusiveRun, validation, stats, Float32Array fix), drop the dead build files and phantom export, native namespace unification + the log-forwarder/teardown/getBackendInfo work (coordinate with #3314). Retire the whisper family (10 workflow files incl. `repository-dispatch-`), remove its `pr-gate-merge`/`prebuilds-caller`/trust-policy entries. Publish behavior at merge, stated plainly: the new `on-merge-transcription-ggml.yml` fires and GPR-publishes `@tetherto/transcription-ggml-mono@0.1.0` (whisper-only) — intended; note `publish-gpr` runs `continue-on-error: true`, so the *first-ever* publish of the new name must be manually verified, not assumed from a green run. No npmjs publish happens here (that requires the `release-*` flow).
**PR 2 — parakeet merges in (history-preserving).** `git mv` parakeet's substantive code: `addon/src/model-interface/{ParakeetStreamingProcessor,ParakeetTypes,parakeet/}`, `src/parakeet.ts` (the driver's native interface), tests, examples, benchmark server/client configs, model manifests and mobile generators (parakeet-only assets — whisper has none to merge). Add the parakeet driver + native branches + dual-port `vcpkg.json`. Delete `packages/transcription-parakeet`, retire its family (9 files), prune its central-registry entries. Merge the two Python WER/CER harnesses and the two RTF aggregator scripts (same shape, ~40% divergent — a merge, not a dedupe). Before the old `on-pr-close-*` files go: **close out the in-flight PRs' ephemeral GPR versions** (the closed-PR cleanup runs from the merge ref; once the workflow is deleted from `main`, leaked `-mono` PR versions are only cleanable via the raw GPR API) — or keep the two files as dispatch-only stubs until the freeze window closes.
**Release — first npm publish (its own PR, per the packages rule).** `release-*` merge with version bump + changelog for `transcription-ggml` → `@qvac/transcription-ggml` on npmjs. **PR 3 is blocked on this**, and so is swapping the published-package registries: `addons.js`, `gate-selftest.yml`, coload-smoke paths/entries flip old→new here (or immediately after), not in PR 1.
**PR 3 — SDK repoint (Ticket A, sequenced here).** The two plugin files import `TranscriptionGgml` + `ENGINE_*` (types too — `WhisperConfig` et al. get re-exported or renamed); `ADDON_*`/`PLUGIN_*` constants; `engine-addon-map.ts` legacy aliases (`@qvac/transcription-whispercpp`/`-parakeet` → canonical, the `onnx-tts` precedent); `bare-sdk` `plugin-addons.mjs`; `sdk/package.json` deps + `ensureprebuilds` script; `sdk/contract/model-type-maps.json` + regenerate the `sdk-python` map; `ai-sdk-provider` schemas; SDK naming tests; tts-ggml's benchmark devDep; `on-pr-bare-sdk-e2e.yml` install line. **Keep both `modelType`s and both plugins** — public SDK API unchanged. Coordinate separately (deployed data, not a repo PR): `registry-server/data/models.prod.json` entries carrying `"engine": "@qvac/transcription-whispercpp"` need alias resolution or a data migration.
**Post-PR 3 cleanup:** docs website (`custom-tree.ts` nav + `content/docs/addons/transcription-*` pages + `ai-capabilities/transcription.mdx`), NOTICE tooling config (`.cursor/skills/qv-notice-generate/.../config.js` — `notice-drift.yml`'s weekly cron will flag it otherwise), `docs/ci/LABELS.md` and release-notes command docs, npm/GPR retirement of the old names per org policy.

**Freeze window — stated honestly**: it runs from PR 1 to the first npm release (not "PR 1 to PR 3"), because old packages can't take changes after PR 1 and the new one isn't consumable off npm until released. Keep it short by having the release PR staged in advance. In-flight PRs: land #3228 before PR 2 (or re-port by hand — the reshape splits files, defeating rename detection); fold #3314's surface into PR 1's `getBackendInfo` work; #3126/#3130 are trivial either way.

**Validation gate per PR**: label-gated prebuilds + desktop + mobile lanes (the family exists from PR 0), plus coload-smoke once the addon list flips at the release step.

Recommendation (revised): **provision a fresh `AWS_DEVICE_FARM_PROJECT_ARN_TRANSCRIPTION_GGML` / `IOS_DEVICE_POOL_ARN_TRANSCRIPTION_GGML` pair.** Repointing parakeet's project is *not* just a secret rename — device pools are project-scoped children, so whisper's mobile coverage would silently become whatever parakeet's pool selects; whisper's own project can't be donated either (shared with BCI). Needs the infra owner before PR 0's mobile lane can run for real.

## Alternatives considered

1. **Keep two packages** — continued duplication and skew; every finding in the Problem section persists, and qwen-asr would become a third copy.
2. **Per-engine subpath exports** (`transcription-ggml/whisper`) — larger public surface, diverges from tts-ggml, and defeats the point (consumers coupling to engines by import path instead of by config).
3. **Fully normalized third config vocabulary** — maximal API elegance, but every field remap is a silent-breakage risk (whisper's key-translation layer is already the fragile spot), it forces nontrivial SDK plugin translation (no longer addon-only), and it throws away whisper's battle-tested `configChecker` allow-lists. Rejected in favor of engine-discriminated config with preserved vocabularies; a normalized *common* layer can grow additively later.
4. **Block on `speech-cpp` (Ticket 4) as the dependency** — serializes this QIP behind an unstarted port for zero consumer-visible benefit; the two-port Phase A is equivalent at the ABI level (same `ggml-speech`) and the swap is one manifest PR later.
5. **Mirror tts-ggml's monolithic orchestrator exactly** — simpler to review against the template, but the ASR engines' JS surfaces and *lifecycles* are far more divergent than the TTS engines'; the inline-branch pattern is already strained with two similar engines. Drivers keep qwen-asr additive.
6. **New package assembled from scratch (no `git mv`)** — loses blame/`git log --follow` across the migration for two heavily-maintained packages. Rejected; rename-only commits first, reshape commits second, per the repo-reorg QIP's convention.
7. **Preserve both packages' current semantics exactly under one API** — impossible where they contradict (exclusiveRun, pause, validation, stats gating); the Decision section picks one behavior per divergence and documents each as a breaking change in the changelog rather than shipping an API whose behavior depends on the engine in undocumented ways.

## Consequences

1. One ASR package, one addon, one CI family (−19/+10 workflow files), one benchmark harness, one Device Farm lane, one `BackendId`/stats vocabulary — full parity with `tts-ggml`, and a clean additive home for qwen-asr (`ENGINE_QWEN_ASR` + one driver + one native model class).
2. SDK breakage stays small and mechanical, but not "imports only": two plugins keep their `modelType`s and per-engine zod schemas; PR 3 swaps imports, *type names*, and constants, and the deployed model-registry data needs an alias/migration pass. The `onnx-tts` → `tts-ggml` precedent covers package-name stragglers.
3. Deliberate behavior changes, documented per-engine in the changelog: exclusiveRun completion-semantics for parakeet, strict model validation for parakeet, structured NOT_SUPPORTED `pause`/`unpause` for parakeet, `stop()` retired for whisper, `Float32Array` input fixed for whisper, stats gating unified.
4. Apps loading both engines ship one prebuild instead of two; apps loading one engine carry the other's engine lib in the addon binary — measured at PR 2, expected small relative to models, and Phase B's feature-gated umbrella port is the lever if it isn't.
5. Costs: the merge effort now explicitly includes native log/teardown/verb unification and a new whisper `getBackendInfo`; a freeze window spanning PR 1 → first npm release; Device Farm provisioning; ~6 weeks of empty perf-report history; reviewers must hold the line on "no per-engine subpaths, no third config vocabulary, method-surface knobs only" as engines accrete.

## Out of scope

1. The umbrella vcpkg port itself (Ticket 4) — only the Phase B swap point is defined here.
2. The SDK repoint lands as its own ticket/PR (Ticket A; sequenced above so this QIP owns the ordering, not the implementation).
3. SDK modelType consolidation to a single `transcription-ggml` type (optional follow-up behind alias machinery).
4. Parakeet typed `vad` events (Phase 2: wire the engine's `StreamEvent` API through the addon — additive).
5. qwen-asr engine implementation.

## Open decisions

1. **Device Farm secrets**: fresh `_TRANSCRIPTION_GGML` project/pool pair (recommended — see Infra) vs repointing parakeet's project and accepting the whisper device-coverage change.
2. **Initial version**: recommendation `0.1.0` (new name, no continuity constraint).
3. **PR 1 API scope**: land the unified constructor/API with whisper-only support immediately (recommendation — keeps PR 2 a pure engine addition), vs keeping the old whisper API until PR 2.
4. **`exclusiveRun` + streaming**: confirm the proposed rule (run() serialized to completion; streaming holds the slot for setup only; concurrent run() during an open session → structured error) with the SDK owners — it changes observable behavior for both engines' edge cases.
5. **Release timing**: cut the first npm release immediately after PR 2 (recommendation — shortest freeze) vs batching with other release-train packages.
